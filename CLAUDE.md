# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A TypeScript library for parsing, modeling and transforming Druid SQL (plus running queries and decoding results). Its main consumer is the Druid web console. The parser keeps whitespace, comments and casing, so `SqlExpression.parse(sql).toString() === sql`. Transformations should change only what they touch.

## Commands

Node is pinned in `.node-version`, managed by mise (`mise exec -- <cmd>` if it is not activated in the shell).

- `npm run build`: compiles the PEG grammar, emits types to `types/`, and bundles to `dist/` with tsup
- `npm test`: builds (via `pretest`), then runs eslint, the prettier check and jest. This is the full gate.
- `npx jest src/sql/sql-table/sql-table.spec.ts` or `npx jest -t "pattern"`: run a subset. It needs the generated parser to exist, so run `npm run build` (or `node script/compile-peg.js`) first after any grammar change.
- `npm run eslint-fix` / `npm run prettify`: autofix lint and formatting

## Architecture

- `src/sql/`: one folder per AST node (`sql-column/`, `sql-query/`, `sql-clause/sql-where-clause/`, ...), each with the class and its `.spec.ts`. Every node extends `SqlBase` (`sql-base.ts`). Nodes are immutable: `change*` methods return new instances, and they are built through static factories (`create`, `optionalQuotes`, ...), not `new`.
- `src/sql/parser/druidsql.pegjs` (plus `druidsql.header.js`): the Peggy grammar. `script/compile-peg.js` compiles it into `src/sql/parser/index.ts`, which is generated and gitignored, so never edit it.
- Adding a node type usually touches: the new class, which calls `SqlBase.register(...)`; its `SqlTypeDesignator` in `sql-base.ts`; the export in `src/sql/index.ts`; the grammar; a spec; and often the README.
- `src/sql/reserved-keywords.ts` is generated by `node script/find-keywords.js`, which needs a Druid router on `localhost:8888`. Don't hand-edit it.
- Other top-level areas: `query-result/` (decoding Druid result shapes), `query-runner/`, `introspect/`, `filter-pattern/`, `shortcuts/` (the `sql` template tag).

## Testing conventions

- Parser round trips use `backAndForth(sql, ExpectedClass)` from `src/test-utils.ts`, which asserts that the SQL parses to that class and prints back identically.
- Tests lean heavily on `toMatchInlineSnapshot`. `jest-env.ts` installs a serializer with `callToJSON: false`, so snapshots show the real object structure instead of `toJSON()` output.

## Conventions

- Every source file needs the Apache 2.0 license header (enforced by eslint `notice/notice`).
- Lint and formatting come from the shared `@awesome-code-style` configs. `npm test` fails on any eslint warning.
- User-facing changes need a changeset: a file in `.changeset/` with `'druid-query-toolkit': patch|minor|major` and a one-line summary. Releases go through the changesets GitHub action.
- The published package has no runtime dependencies. Keep it that way.
